## Objective

Create a functional Web UI for Hermes Portable that provides:
1. Chat interface for AI conversations
2. System status monitoring
3. Configuration management

## Key Findings

### Hermes Built-in Dashboard
- `hermes dashboard` command exists (port 9119)
- Requires `npm run build` which hangs in our environment
- `web_server.py` is a full FastAPI application with management APIs
- **No built-in chat API** - Dashboard is for config/sessions/cron, not chat

### Ollama Status
- Running on port 11434 (PID 24420)
- API calls timeout when model not loaded (60s+ delay)
- 7 models available: qwen3.5:0.8b, bge-m3, gemma4:31b-cloud, etc.

### Solution Architecture
Built a **unified Python HTTP server** that:
- Serves static HTML from `web_dist/`
- Provides REST API endpoints
- Integrates with Ollama for chat
- No npm/Node.js dependency

## API Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/status` | GET | System status (Python, Hermes Home, etc.) |
| `/api/ollama/status` | GET | Ollama running status |
| `/api/ollama/models` | GET | List available models |
| `/api/chat` | POST | Send message to Ollama |
| `/api/chat/history` | GET | Get chat history |
| `/api/chat/clear` | POST | Clear chat history |
| `/api/config` | GET/POST | Get/save Hermes config |

---

## Technical Notes

1. **Ollama Response Time:** First request to a model may take 30-60 seconds (model loading). Subsequent requests are fast.

2. **Chat History:** Stored in-memory (cleared on server restart). For persistence, modify `dashboard_server.py` to save to file.

3. **CORS:** All API responses include `Access-Control-Allow-Origin: *` for cross-origin access.

4. **Model Selection:** The UI auto-detects available Ollama models via `ollama list` command.
